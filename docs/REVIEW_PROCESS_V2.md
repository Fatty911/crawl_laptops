# 评审流程 v2：证据驱动评审（2026-08-10 起强制）

## 背景：为什么 v1 评审失效

回顾 2026-08-08~10 提交链，评审每次 PASS 但线上持续出问题：

| 问题 | 为什么 v1 评审没发现 |
|---|---|
| 机械师 126 条外设垃圾混入 | 评审只看 diff 摘要，不抽查 artifact 实际内容 |
| "笔记本电脑包"逃过 is_notebook | 语义问题（含"笔记本"字样）不在代码 diff 里 |
| F117-b8p ¥499 异常低价 | 价格合理性不在评审范围 |
| ThinkBook 集显版显示 RTX 4060 | dedicated_gpu vs gpu 字段矛盾，diff 看不出来 |
| 正则 \\s 写成 \\\\s（转义 bug） | 语法合法，评审模型不检查转义语义 |

**根因**：评审 prompt 只含提交者自述（"实测 304 tests 全绿"），
评审模型**无法验证数据语义**，PASS 变成格式检查而非质量检查。

## v2 强制流程

每次提交前运行：

```bash
python3 scripts/review_gate_v2.py --summary "改动摘要" --diff-description "技术描述"
```

### 自动步骤（review_gate_v2.py 内部）
1. `collect_review_evidence.py` 收集**真实机器证据**：
   - pytest 输出（真实失败详情）
   - artifact 数据质量抽查（垃圾词命中/低价<500/GPU 矛盾/正则转义）
   - 变更文件清单
2. 证据注入评审 prompt（不是自述！）
3. 评审模型**必须核验证据**后 PASS/FAIL
4. 证据显示任何数据质量问题 → 必须 FAIL
5. 评审模型无法输出标准 PASS → 拒绝标记（不伪造）

### 数据语义检查清单（每次强制）
- [ ] 新数据源：JUNK 词命中数必须 0（外设/配件/包）
- [ ] 价格合理性：<500 异常价必须 0
- [ ] 字段一致性：dedicated_gpu vs gpu 矛盾必须 0
- [ ] 正则转义：raw 字符串双反斜杠必须 0
- [ ] 多源合并防误并：具体 CPU 型号不同不合并、配置冲突不合并
- [ ] 重复 identity：同配置签名重复必须 0

### 手工补充检查（提交者仍需做）
- 下载最新 artifact 抽样目检（前 10 条 title 分类）
- 新数据源全量内容审查（不只前几条）
- 弱证据必须类目前置（外设不能有"游戏本弱证据"）
